# 开发路线

按 Phase 0 至 Phase 14 顺序推进。每阶段依次完成需求分析、技术设计、实现、验证、文档记录和验收。验收汇报新增和修改文件、实现原理、测试方法、实测结果及已知问题，获得用户确认后进入下一阶段。修改现有代码前先建立可恢复版本。

## 阶段与验收条件

| 阶段 | 范围与交付物 | 验收条件 |
|---|---|---|
| Phase 0 · 需求与初始化 | README、需求、架构、路线、技术选型和本地 Git 仓库 | 五份文档和目录一致，内部链接可解析，原有文件完整。 |
| Phase 1 · 开发环境 | 检查 Python 3.12、虚拟环境和 Ollama，复测本地模型。添加 `pyproject.toml`、`.gitignore`、`.env.example`、基础运行脚本与环境文档，配置 Git。 | 按文档可复现环境及启动流程。Git 忽略虚拟环境和本地密钥。 |
| Phase 2 · LLM 接入 | Ollama Client、模型测试程序与实测记录。覆盖基础聊天、多轮、流式、结构化输出、推理和工具调用兼容性。 | 逐项记录真实请求的输入、输出、耗时或错误，并标记兼容性限制。 |
| Phase 3 · 模型接口 | `BaseLLM` 和 `OllamaLLM`、统一消息和结果、日志、异常与超时、单元测试。 | 正常响应、服务异常、超时和格式错误均有可复现验证。 |
| Phase 4 · Function Calling | JSON Schema、工具调用 Demo、参数校验及工具结果回传、工具调用测试集。 | 有效请求可执行并回传，非法参数被拒绝。分别统计工具选择和参数生成准确率。 |
| Phase 5 · 工具系统 | `BaseTool`、`ToolRegistry`、统一执行结果、计算器、文件读取、搜索接口及工具测试。 | 验证工具注册、查询和分发。搜索提供方按可用配置接入，接口可用桩测试。 |
| Phase 6 · Agent Loop | 独立 Agent Engine、多工具 Demo、循环测试。支持结果回传、步数、时限和终止原因。 | 含连续多次工具调用的任务可以退出，反复调用与超时用例按预算停止。 |
| Phase 7 · 规划与任务管理 | Planner、Executor、Task Manager 和多步骤任务测试。管理依赖、优先级、完成条件及重试。 | 可验证任务排序、依赖失败传播和有限重试。 |
| Phase 8 · 记忆与状态 | SQLite、Memory 模块、对话和任务历史、检查点和恢复测试。 | 可查询跨进程保存的记录，重启后从检查点继续执行。 |
| Phase 9 · RAG 与知识库 | PDF、TXT、Markdown 解析，清洗、切分、嵌入、向量索引、相似度检索及上下文注入。提供检索 Demo 和质量测试。 | 固定问题可找回预期片段，片段能定位到源文件。重排序纳入后续实验。 |
| Phase 10 · 研究流程 | 完整 Research Agent 和报告 Demo。接入已选的搜索提供方，抓取网页，分析和综合证据，生成并审查引用。 | 用真实主题生成 Markdown，引用可以逐条核对。记录失败来源、证据缺口与来源冲突。 |
| Phase 11 · 评估 | 评估框架、数据集和性能报告。记录完成率、工具和参数准确率、平均耗时、失败率、Token 与资源使用，建立模型对比实验。 | 相同样例和记录口径下可以重跑对比，报告注明环境和样本量。 |
| Phase 12 · 安全与异常 | 完善工具权限、注入防护、文件边界、敏感操作确认，以及命令、超时、重试和 Token 预算。 | 越权路径、文档内恶意指令、预算耗尽和异常恢复均有验证。任意终端执行默认禁用。 |
| Phase 13 · 前端与后端 | Streamlit、FastAPI、API 文档。支持聊天、创建任务、状态与工具记录、历史、文档上传、报告展示和导出。 | 通过界面和 API 各验证从任务创建到报告导出的链路。 |
| Phase 14 · 部署与交付 | 部署说明、技术文档、GitHub 项目整理、演示、回归测试、资源与执行效率优化。 | 可按说明从干净环境复现演示，优化结果有同口径的前后数据。 |

搜索接口和真实搜索服务分别验收。Level 1 的三个工具以真实可运行为准，待第三个工具通过验证时验收。Level 2 按完整应用验收，Level 3 以可复现实验验收。Phase 14 之后可继续研究上下文压缩、并行工具执行、多 Agent 协作、模型对比、推理性能及 LangGraph 与自研工作流对照。

## Phase 0 验收记录

- 已核对五份 Markdown 文档、八条本地链接和 Phase 0 至 Phase 14 的排列顺序。Git 仓库以 `main` 为初始分支，仓库根目录与工作区一致。
- 通过 SHA-256 对比确认原脚本和虚拟环境配置在初始化前后内容一致。按 README 命令复跑原脚本，退出码为 `0`，获得 2384 个回复字符。以 UTF-8 捕获并解码确认包含有效中文。
- 本阶段交付目录见 [README](../README.md#目录)。环境配置和模型能力测试分别在 Phase 1 和 Phase 2 验收。

## Phase 1 验收记录

- 复用 Python 3.12.10 虚拟环境并完成可编辑安装。`pip check` 无冲突，模块入口和安装后的命令行入口均通过环境检查，检测到 Ollama 0.40.17 与 `qwen3.5:4b`。
- 确认 Git 提交身份可用，虚拟环境和本地环境文件已被忽略。用法见 [Windows 开发环境](environment.md)。

## Phase 2 验收记录

- Ollama Client 和 `model-check` 命令已完成。短提示实测通过 6/6，具体输入判定与耗时见[本地模型能力实测](model-capabilities.md)。

## Phase 3 验收记录

- `BaseLLM` 与 `OllamaLLM` 提供统一消息、工具描述、结果和 Token 统计。适配层处理异常、网络超时及日志。
- 9 项单元测试通过。切换到新接口后的本地模型复测通过 6/6。

## Phase 4 验收记录

- Function Calling Demo 已验证原生工具请求、参数校验、固定数据查询、工具结果回传。新增 4 项单元测试，累计 13 项通过。
- 最终测试集的工具选择、精确参数和端到端结果均为 6/6。两次早期运行的回传格式偏差及提示调整见 [Function Calling 实测](function-calling.md)。

## Phase 5 验收记录

- 已完成工具注册、查询、参数校验、执行分发和统一结果。计算器、文件读取和搜索提供方接口的使用见[工具系统](tools.md)。
- 累计 27 项单元测试，26 项通过，1 项因 Windows 缺少符号链接创建权限而跳过。独立验证了 Windows 目录联接的越界拒绝。
- 计算器与文件读取均已通过真实模型请求和注册表执行验证。搜索已通过桩测试，待选择并配置联网服务。

## Phase 6 验收记录

`agent-demo` 在真实本地模型上用三个模型回合完成 `read_file → calculator → 137`。每轮的工具结果按顺序回传，未知工具和参数失败也作为结果回传。默认预算为 6 次模型请求、12 次工具调用和 120 秒。模型请求收到剩余时间，执行器在调用边界检查截止时间。同步工具执行由工具自身返回，截止时间无法强制中断已经开始的工具。

新增 5 项测试，覆盖批量回传、多轮、步数和工具预算、截止时间及模型错误。累计 31 项通过，1 项因 Windows 符号链接权限跳过。

## Phase 7 验收记录

`plan` 用本地模型为 SQLite 日志模式对比生成了三个有效子任务，包含优先级和依赖。TaskManager 验证任务图并按依赖和优先级排定顺序。Executor 传递已完成的前置结果，重试可恢复失败，依赖失败时阻塞下游。

新增 4 项测试，覆盖计划验证、顺序、重试和阻塞传播。累计 35 项通过，1 项跳过。

## Phase 8 验收记录

SQLite 保存计划、任务尝试次数、中间产物和对话消息。执行时使用内存历史，完成或中断后通过数据库查询。每次尝试先写检查点，终态数据与该次消息可在同一事务写入。同一任务运行由进程锁保护，进程退出时释放。

真实子进程写入检查点后直接退出。新进程恢复时跳过已成功任务，从中断任务的第二次尝试继续，成功读取前置结果并得到 `14`。`history` 查询显示两项均完成。新增 4 项测试，累计 39 项通过，1 项跳过。

## Phase 9 验收记录

完成数字 PDF、UTF-8 TXT 和 Markdown 的提取与定位、EmbeddingGemma 批量嵌入和 CPU FAISS 检索。真实模型的三条固定查询 Top 1 均命中预期文件，包含定位到 PDF 第 1 页。新增 5 项测试，累计 44 项通过，1 项跳过。[本地知识库](retrieval.md)

## Phase 10 验收记录

`research` 使用模型计划、SQLite 检查点、本地 RAG 和可选维基百科搜索执行研究。Markdown 报告标注检索、任务和证据不足的问题。原文匹配与模型复查均已接入。首轮本地报告因计划过宽而缺少结论，后续收紧了计划范围和输出约定，并补充了 WAL 恢复资料。最终本地报告保留 3 条、联网报告保留 1 条通过检查的结论。恢复已完成任务的报告哈希一致。[报告和复现步骤](research.md)

新增 8 项测试，累计 53 项中 52 项通过，1 项因 Windows 符号链接权限跳过。

## Phase 11 下一步

把任务成功、引用质量、工具失败、时延和 Token 使用纳入固定样例评估。评估时分别记录检索命中、引述匹配和模型复查结果。
