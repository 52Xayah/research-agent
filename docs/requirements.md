# 项目需求

## 目标与使用场景

面向需要调研技术问题的用户，例如「对比 SQLite WAL 与默认日志模式在小型 Python 服务中的适用场景」。用户输入主题，可附带研究范围和本地资料。Agent 拆解问题，获取证据，生成结构清晰、来源可追溯的 Markdown 报告。目标运行环境为 Windows、Python 3.12 和本地 Ollama。

## 功能需求

| 编号 | 需求 | 可观察结果 |
|---|---|---|
| FR-01 | 理解目标并自动制定研究计划 | 执行记录包含研究问题、子任务、优先级和依赖关系。 |
| FR-02 | 自主选择和调用已注册工具 | 每次调用有工具名、校验后的参数和结果。失败分类可见，达到执行预算后结束。 |
| FR-03 | 搜索和读取资料 | 能经配置的搜索服务获取网页来源，解析获准访问的 PDF、TXT 和 Markdown。 |
| FR-04 | 检索与交叉验证 | 找回相关片段及出处，记录结论与证据的关系，对来源冲突和证据不足单独说明。 |
| FR-05 | 管理任务与记忆 | 可以查询任务状态、对话、计划及中间结果。中断后依据持久化状态恢复。 |
| FR-06 | 生成并检查报告 | Markdown 报告包含主要结论、依据、来源清单与局限。引用指向已获取的来源及可定位的证据。 |
| FR-07 | 提供图形界面和 API | 支持创建任务、跟踪状态和工具记录、上传资料、查看历史、查看和导出报告。 |
| FR-08 | 评估运行质量 | 固定样例集记录任务完成率、工具和参数准确率、延迟、工具失败率与模型资源使用。 |

## 约束与边界

- 以 RTX 4060 Laptop GPU（8 GB 显存）和 16 GB 内存为设计基准。按阶段实测延迟与内存占用，控制上下文、资料大小、结果条数和执行步数。
- 默认通过 Ollama 使用 `qwen3.5:4b`。搜索通过可替换的接口接入，配置项需要描述配额、超时和错误处理。密钥通过运行环境提供。
- 研究流程以读取和分析资料为主。文件读取限定在授权目录内，网页内容和文档作为数据处理。默认禁止任意终端命令执行，敏感操作需要人工确认。
- 报告引用应能定位到链接、PDF 页码或文本段落。来源内容、模型综合判断和未解决的问题应有清晰标识。证据不足时，把缺口写入报告。
- 网页访问失败、搜索服务未配置或达到配额时，在任务记录中说明影响。已取得的资料可继续用于支持范围适当的结论。

## 最终验收等级

| 等级 | 验收要求 |
|---|---|
| Level 1 · MVP | 本地模型可用，至少 3 种工具通过真实执行验证。能连续调用多个工具完成简单多步骤任务，并处理参数错误、工具失败与步数上限。 |
| Level 2 · 完整 Research Agent | 从主题出发自动规划，搜索并读取网页、解析本地 PDF、使用 RAG、保存任务状态、生成有来源的报告，并通过图形界面演示和固定样例评估。 |
| Level 3 · 深入研究 | 以相同任务集对比模型及工作流，量化执行效率、上下文压缩和并行工具调用的影响，并记录实验条件。 |

每项验收记录执行方法、输入、环境和实际结果。搜索接口的桩实现用于测试，工具数量按实际接入并运行的工具计算。
